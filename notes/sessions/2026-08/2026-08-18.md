## THE GATES — Tinkerer · Manual · Debug (`0.44.17` → `0.44.18-alpha`)

The day's one architectural change, and the thing to read first if you are picking this up cold.

### The shape

There are now **two** buttons at the right of the map toolbar, and they answer **two different
questions**:

| Button | Question | Contents |
|---|---|---|
| **`!`** | *Is this value real?* | Unused & unstable · No-effect edits · Truly unused |
| **🔧** (wrench) | *Do I want to work at this level?* | **Tinkerer** · **Manual** · **Debug** |

Leadership's words, and the reason they are not one button:

> *"Tinkerer, Debug and Manual should be their own icon next to the exclamation point icon, which
> should still contain the 3 it has."*

They were briefly stacked into the `!` popup and that was wrong. Everything under `!` is a value the
game does **not** honour (dead, wiped, never read); everything under 🔧 is a value it honours
perfectly well. Merging them would have made "why can't I see this?" a two-part answer.

### The rule that makes it work

> *"An option is ONLY gated by 1 box. An option NEVER requires 2 or more gates to be enabled for it to
> show, just like an option will never BELONG to any more than 1 gate only. This keeps things simple
> and clean."*

**Flat and exclusive**, and enforced by *shape* rather than by discipline:

- **In the model** (`MapModel::warpStateFields`), a field carries at most one `gate` **string**
  (`""` / `"tinkerer"` / `"manual"` / `"debug"`). One funnel — the `add()` lambda — reads it; a field
  with no gate falls through to the old scratch/dead question. There is nowhere to put a second gate.
- **In QML** (`CharacterStatePanel`), a row carries one `gate` **string** property, resolved through a
  `gateOn` map. Same reason.
- ⚠️ **When a row is both rewritten-on-load and finicky, `scratch` wins.** Not a coin-flip: "the game
  will throw this away" is the fact that decides whether editing it is worth anyone's time, and it must
  not be reachable from a gate that doesn't say so.

### And a gated-empty panel takes its tab with it

> *"If a whole panel ends up being hidden the panel itself and its tab need to disappear for clean UX."*

Enforced at the **rail** (`Map.qml` → `rightDock.panels`), because that is the one place that decides
what exists. **Character state** is the live case: *every* one of its rows is gated (four no-effect,
three Tinkerer, one Debug — the 2026-07-15 research found not one ordinary edit among them), so with all
gates shut it would be an empty page, and its rail button now simply isn't there. Verified on screen:
the right rail goes 3 buttons → 4 when Tinkerer opens.

Group headings inside a panel follow the same rule at their own scale — each carries the OR of its own
rows' gates, because a heading with nothing under it is worse than no heading.

### What went behind each gate

**Tinkerer** — real, durable, console-honoured values that describe a state a save has no business
resting in:

- `CharacterStatePanel`: Scripted walk — starting · Scripted walk — running · Trainer battle queued
- `WarpStatePanel` (via the model): `specialWarpDestMap` ("Fly sends you to") · `whichDungeonWarp`
  ("…through hole #") · `warpDest` ("Arriving at warp #") · `flyOrDungeonWarp` ("A special warp is in
  progress")
- `MapNamePicker`: the whole **Tileset & blocks** disclosure
- `ContrastPicker`: the six **glitch contrast** values (its own local switch is gone — leadership:
  *"perhaps remove the 'Glitch contrast' switch and instead have it placed behind [the gate]"*)

⚠️ **Deliberately NOT gated** (leadership named the harmless, fun ones to leave alone): "Falling drops
you onto" · "You fell down a hole" · "Dig / Escape Rope / blacked out" · "Warps fire without walking
into them".

**Debug** — the founding member is the **test-battle switch**. Leadership: *"Unused and unstable should
no longer include debug or developer stuff, that is moved to its own gate out of unused and unstable."*
That tier's blurb no longer has to say "developer leftovers", so it is one clean idea again: *the game
reads it, acts on it, and the result is unintended.*

**Manual** — the hand-controls for values the app keeps in sync:

- a connection's **Raw bytes** section + its "Break sync" switch (`DetailsPanel`)
- the **camera / view box** — the loose/attached switch and the raw address (`DetailsPanel`)

> *"It includes the manual controls like viewbox and connection — it doesn't switch them to manual, it
> just shows them, allowing to break auto sync."*

**Read that carefully, because it is the whole design: the gate REVEALS, it never SETS.** Sync stays on,
the bytes stay derived, the fields stay read-only until you throw the switch yourself. Opening a gate
must never be an edit.

⚠️ Each keeps an **escape hatch that is not a second gate**: a connection already desynced
(`synced === false`), a camera already loose (`!viewSynced`), a save already sitting on a glitch
contrast (`contrastIsGlitch`) shows its controls whatever the gate says — otherwise the panel would be
hiding the only explanation for what the map is doing. Same shape in all three places.

### Pinned

`tst_warps::tinkererFields_areAbsentUntilThatGateIsOpen` asserts **both halves** of the rule:

1. the four mid-motion bytes are absent with the gate shut,
2. **and turning on every `!` tier does not reveal them** — the negative is the half that stops the two
   systems bleeding into each other the next time someone adds a field.

Three existing `tst_warps` cases needed `setShowTinkerer(true)` because they read gated fields.

### Files

`mapmodel.{h,cpp}` (the three `show*` properties + setters — each emits `changed()` as well as its own
signal, because the dock rebuilds its rail off `changed()`) · `MapIdentityBar.qml` (the wrench button +
its popup) · `Map.qml` (the conditional rail) · `CharacterStatePanel.qml` · `ContrastPicker.qml` ·
`MapNamePicker.qml` · `DetailsPanel.qml` · `tst_warps.cpp`.

## The rest of the day, in the order it happened

### Indoor / Cave / Outdoor is its own section now

> *"Basically overhaul the indoor/cave/outdoor section and separate it from tileset and blocks. Actually
> gate tileset and blocks behind the Tinkerer gate."*

It had been living **inside** the Tileset & blocks disclosure, which put a choice anybody might want to
make — does this map's water move? can I Surf here? — behind a collapsed heading about ROM pointers, and
then behind a gate as well. It is now its own titled section (`"Indoor, Cave or Outdoor"`) in the map
selection panel, above the gated disclosure.

### The animation bullets, three corrections in one day

This section was rewritten **three times** and the sequence is worth keeping, because each correction
was right and they pull in different directions.

1. **Over-simplified.** *"wait youve removed important data from the indoor/cave/outdoor, the wording
   seems oversimplified in some ways, theres only 2 bullet points and we're missing other data that was
   there… This needs to be way better you de-improved it a lot."*
2. **Then over-technicalised.** *"now you took ux away going against my design decisions. I dont want
   technical info dumps like 21 frames bytes rotated — this isnt plain english, this is technical
   jargon and its not nesesarily more useful for any group of people."*
3. **Then the marks came off.** *"Dont include exclamation point tooltips on the pros/cons, they
   effectively say the same thing. It should just be an icon, the tooltip text should instead be the
   already existing pro/con text you made."*

**Where it landed, and the rule it is written to: say what you will SEE, not how the console does it.**
The frame cadence, the byte rotation and the flower's frame order are all true and all belong in
[`reference/map-animation.md`](../../reference/map-animation.md), which is where they now live alone.

The vocabulary is now exactly `{ text, pos }` and `{ text, note: true }` — a green `+`, a red `−`, an
amber `⚠`. The `warn` key (a second yellow `!` with a longer explanation) is **gone**: every one of them
was a paraphrase of the sentence it hung off. The `+/−/⚠` icon carries the bullet's own sentence as its
tooltip, which also rescues the text when a long bullet wraps tight.

Two more calls from the same pass:

- **No `!` on the segment strip.** *"Forgo the exclamation mark, just keep the green dot on the
  default."* (`animHasWarning` is deleted, not stubbed.)
- **The default is a DOT, never a bullet.** *"Don't have tileset's own setting, it's not a pro or con,
  it's just a map default option — it's what the green dot is for."*
- **Surf is a property of the SETTING, not of the moment.** *"Dont determine surfing by if the player is
  actively surfing — most of the time they may not be; just because there not doesnt mean the map is ok
  to make non-surfable."*

### The map picker stays open when you pick a map

> *"When changing maps don't close the map screen, it's annoying — sometimes I want to scroll through
> maps and click different ones."*

Exactly the right read of what that control is for. A pick is a **preview** (`beginMapPreview`), and
previewing is inherently something you do several times in a row; closing after each one turned browsing
into reopen-scroll-find-click, and threw away the scroll position and the search text every time. It now
closes the way every other popup does — click off, or Escape.

### The connection picker joins the shared selector

> *"the connection map select doesnt use the new shared map select it should default there to
> connections sorting"*

`ConnectionArrow.qml` was the last map picker on the screen still running its own bespoke `ComboBox` —
no search, no sort, a different row shape from every other map list in the app. It now uses
**`MapSelectList`** and opens on **`MapModel.SortConnections`**, which is the sort that answers the
question being asked (you are choosing a neighbour, so cluster the list by which edges a map already
connects on).

- ⚠️ `mapSort` is deliberately **global and shared**, so this is a nudge **on open** and nothing more.
  Change the sort while the picker is up and it stays changed, here and everywhere. A picker that
  re-imposed its own on every frame would be taking the choice back.
- **What the bespoke list did better is kept:** the map the cartridge really connects to that edge rides
  at the top as a `leadingEntries` row under its own heading. No sort can know that — it is a fact about
  this map's ROM header, not a property of the list.
- `margins: 8` on the popup, because a short combo became a tall list and an arrow near the bottom edge
  opened it half off-screen.
- `MapSelectList` now tolerates a leading row with no `isCopy` key (`visible: undefined` is a QML
  warning, not a quiet false — it failed `tst_qml_screens`).

### The connection tooltip was dark-on-dark

> *"also the connection tooltips are dark text on dark background make it proper how it is elsewhere"*

`ConnectionArrow.qml` was the **last file on the map screen still using the stock `ToolTip`**. The rule
is written at the top of `MapToolTip.qml` and it is absolute — *"if you are typing `ToolTip`, you want
`MapToolTip`"* — and this was the holdout. Fixed, and the bullet tooltip I had just added in
`MapNamePicker` was fixed with it (I had written `ToolTip.text`, breaking the same rule minutes after
citing it).

## Traps and lessons from this day

- **A QML `visible:` bound to a missing object key is a WARNING, not a false.** `visible: modelData.isCopy`
  on a hand-built row without that key → *"Unable to assign [undefined] to bool"* → `tst_qml_screens`
  red. Write `=== true` for any optional key. (`size` in the same delegate was already defensive; this
  one wasn't.)
- **`MapModel`'s enums are reachable from QML but need the import.** `MapModel.SortConnections` requires
  `import App.MapModel` — it is registered `qmlRegisterUncreatableType` in `bootQmlLinkage.cpp`, but the
  import is what makes the `Q_ENUM` visible. Better than a bare `3`.
- **The harness screen name is `maps`, not `map`.** `Router::screens.insert("maps", …)` — `--screen map`
  silently leaves the app on Home with the New File modal up, which looks like a QML failure and isn't.
- **`app_tap` by coordinate is unreliable; `app_tap` by `objectName` is not.** Several toggles refused
  synthetic clicks at computed coordinates. Added `objectName`s (`mapGatesButton`, `gateTinkerer`,
  `gateManual`, `gateDebug`, `connArrow0..3`) and drove them by name — instant. **If you need to click it
  twice, give it a name.**
- **The MCP job registry can drop a long job** (`job_wait` timed out, then `job_status` reported "no
  job"). `run_ctest` + polling `job_status` in short hops works; so does reading
  `tmp/mcp-jobs/<id>.log` directly.
- **A detached PowerShell `ctest` can be killed with the shell that launched it.** A run stopped dead at
  90/92 with no summary when my `Start-Process` call timed out. Use the MCP `run_ctest` for the full
  suite.
- **Running the app holds `PokeredSaveEditor.exe`.** A kit-dir build fails at the link step with
  *"Permission denied"* — `app_stop` first. (Also: `tst_*.exe` run from a bare PowerShell without the Qt
  `bin` dirs on `PATH` exits `-1073741515` = `STATUS_DLL_NOT_FOUND`, which looks like a crash and is a
  missing `PATH`.)
